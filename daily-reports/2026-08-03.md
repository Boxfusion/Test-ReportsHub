## 4. Findings withdrawn — please note if any were actioned

**Six** earlier conclusions were **wrong** and have been corrected in place (evidence retained, conclusions
changed). Two were caught by the test lead reproducing them manually:

0a. **"A tender can be saved that closes four days before it opens."** **Withdrawn — the app is correct in every
   direction.** The closing picker greys out every day up to the publication date; changing the publication date
   auto-clears an invalid closing date, marks it required and disables Next; and typing with Enter is refused too.
   My invalid pair came from clearing the field with Playwright's `fill('')` — a programmatic write that leaves the
   component's state stale. Not reachable by a user. **The bug doc has been deleted.**

0b. **"The mandatory Supporting Document is not enforced."** **It is** — Next stays disabled until the attachment
   is added. Two documents had already been uploaded before I observed Next enable, so I never tested the
   without-attachment case. Withdrawn.

1. 🔴 **"CRITICAL: a non-bidder was AWARDED a tender."** The module test lead ruled this is **by design** — when
   no bid qualifies, *Recommend another Supplier* is meant to reach beyond the tender's respondents.
   **This is currently live on GitHub Pages with the wrong severity** (shipped in PR #26); the correction is in
   this pending push. Surviving from it: the picker lists every supplier **×10**, and an already-evaluated
   bidder returns a raw silent **500**.
2. **"Non-responsiveness is indistinguishable from a cancellation."** ADO #60835/#60836 route both to
   "cancelled" **deliberately** — being indistinguishable is the intended design.
3. **"The Cancel Tender dialog's *disapproval message* wording is a copy defect."** ADO #60836 step 33 uses that
   exact phrase.
4. **"The total-must-be-100 rule and the disabled Next are undocumented."** Both are specified in ADO #57475.

**Root causes, and the checks now in place:**

1. **Findings were classified from intuition instead of the ADO steps**, which prescribe expected results verbatim.
   → **Read the test case before assigning a severity** (one MCP call).
2. **Automation drove controls in ways a user cannot.** Setting an AntD date field with `fill()` / `fill('')` /
   `pressSequentially` bypasses the component's own logic and can push states into the record that the UI would
   never allow. → **Drive the picker panel — day cell → hour → OK — never write to the input.**
3. **A control's state was read as evidence about the wrong field.** When a button changes state, only the *last*
   thing changed is evidenced. → **Run a control with a known-valid value before concluding.**

Between them these produced four of the six withdrawals and two inconclusive probes. Worth noting that the app
came out of this **stronger than reported**: several "missing" validations were there all along.

## 5. Coverage gap found — a test case with no test

**ADO #60824 "BEC Member: Calibrate Scores and Finalise Scoring" had no test case in our plan.** The suite holds
18 cases; the plan covered 16.

It was invisible because TC-10/TC-11 cover the **Secretariat's** calibration tasks, so calibration looked
complete. But **#60815** states that Begin Calibration *"should send items to **both** BEC Secretariate to monitor
calibration **and BEC Members to calibrate scores**"* — a parallel branch that has never been driven. Every run to
date has passed *through* calibration without any member adjusting a score, which is the half where scores
actually change.

Added as **TC-35** (reached via BID Management → Evaluate Tenders → double-click, not the Inbox). **Not yet run.**
